# v0.9 — Core platform split for macOS: measured inventory

**Date:** 2026-07-29
**Purpose:** the concrete work list for making `Core` platform-neutral (project 3 of the
v0.8 spec), which is the prerequisite for any Mac build. Produced by static analysis of
the actual coupling, not guesswork.

## Shape of the split

```
PrimeOSTuner.Core          net9.0          models, stores, stats, parsing, view logic
PrimeOSTuner.Core.Windows  net9.0-windows  everything below
PrimeOSTuner.Win           net9.0-windows  unchanged (interop clients)
Crustcut.Presentation      net9.0          after the split (today it is -windows)
```

## What has to move or be abstracted (measured)

**21 files import `PrimeOSTuner.Win` directly** — 18 are hand-written tweaks
(registry/power interop via interfaces that should live in Core with impls in Win), plus
`GameRegistry` (launcher scanners), `ProfileLifecycleService`, `SystemSampler`
(IHardwareClient). Fix: move the INTERFACES (`IRegistryClient`, `IPowerPlanClient`,
`IHardwareClient`, scanner interfaces…) into Core and drop Core→Win project reference;
the tweaks themselves move to `Core.Windows` since the concepts are Windows-only.

**2 files P/Invoke:** `Memory/WorkingSetTrimmer` (psapi/user32/kernel32),
`Sentinel/GpuPerfCounterMetricsSampler` → `Core.Windows`.

**7 files use WMI / ServiceController / PerformanceCounter:** DiagnosisProbes,
SystemStateProbe, WmiProcessWatcher, GpuPerfCounterMetricsSampler, DriverHealthCheck,
ServiceClient, WindowsUpdateCache → `Core.Windows`.

**10 files shell out to Windows executables** (powercfg, ipconfig, pnputil, powershell,
schtasks): AppxClient, DiagnosisProbes, six tweaks → `Core.Windows`.

**Stays platform-neutral Core (the valuable part):** all stores (ResilientJsonFile,
settings/history/rules/sessions), FrameTimeStatsCalculator + parser, PriorityRule
model + migrations, SafeRamCleaner protection logic (pure), NavCatalog/view-models via
Presentation, guides/markdown, bloatware catalogs (data), Sentinel rules.

## Mac capability layer afterwards (project 4)

Monitoring (host CPU/RAM via /usr/bin/top or Mach APIs), login items, cache cleanup,
app uninstall + leftovers. No registry/tweak surface exists on macOS — the Optimize tab
becomes Windows-only by feature flag from `NavCatalog`.

## Estimate

The split is mechanical but wide: ~40 file moves, namespace churn in tests, and a
`TweakCatalogWindows` composition entry. One focused session. Do it BEFORE adding any new
Core features so the churn only happens once.
