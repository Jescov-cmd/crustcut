## Looking at the UI (important — read before changing any XAML)

The app screenshots itself. Win32 capture does **not** work here: `PrintWindow`
returns solid black for GPU-composited Avalonia windows, and a plain screen grab
catches whatever window is in front.

```sh
Crustcut.App.exe --screenshot out.png [--screenshot-tab Optimize] [--screenshot-size 920x600]
```

Always look at the PNG after a XAML change. Three separate rounds of "fixed" work
this session were wrong because the XAML compiled and the app ran, so it looked done.

## Two failure modes that bit repeatedly

1. **`DynamicResource` fails silently.** Deleting a key from `Tokens.axaml` does
   not break the build — every reference just falls back to a Fluent default.
   After renaming or removing a token, grep the views for the old key.
2. **Opt-in class styling leaves gaps.** Button styling was class-based, so any
   button missing `Classes="primary"` fell through to Fluent defaults. Base
   `Selector="Button"` now catches everything; variants only override colour.
   Prefer element selectors over class selectors for anything that must be
   uniform.

## Remaining — roughly in priority order

**Wrong behaviour (not cosmetic)**
- **FPS figures are nonsense** — recorded sessions read 714–986 avg. Suspect the
  frametime maths or the PresentMon parse, not the display.
- **Every Memory rule defaults to `BelowNormal`**, including editors like VS Code.
  Check what `RescanRunningAppsAsync` assigns; that default looks wrong.
- **No way to delete a Memory rule** — priority can be changed, rules cannot be removed.

**Must fix before any release**
- `src/Crustcut.App/app.manifest` is `asInvoker`. It must return to
  `requireAdministrator` or every tweak silently fails for lack of rights.
- Autostart scheduled task still points at the WPF exe path.
- Validate self-contained single-file publish for the Avalonia app.

**Not built**

- **Windows display scaling (125% / 150%) is untested.** Window resizing was
